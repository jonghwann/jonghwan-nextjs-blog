Claude를 업무에 활용하다 보면 이런 상황이 반복됩니다.

PR 리뷰를 부탁할 때마다 "우리 팀은 이런 기준으로 봐줘", 커밋 메시지를 작성할 때마다 "우리는 이 형식을 써", 문서를 작성할 때마다 "우린 이런 구조로 작성해"...

매번 같은 맥락을 설명하는 게 꽤 번거롭죠. 이걸 해결해주는 게 바로 **Skills**입니다.

## Skills란?

Skills는 Claude에게 특정 작업이나 지식을 한 번 가르쳐두면, 이후 관련 상황에서 **자동으로 적용**되도록 만드는 마크다운 파일입니다.

각 Skill은 하나의 폴더로 구성되며, 폴더 안에 `SKILL.md` 파일을 두는 방식으로 만듭니다.

```markdown
.claude/
└── skills/
    ├── pr-review/
    │   └── SKILL.md
    └── commit-message/
        └── SKILL.md
```

`SKILL.md` 파일의 맨 윗부분에는 `Frontmatter`라고 불리는 설정 구간이 반드시 들어가야 합니다.

```markdown
---
name: 스킬 이름
description: 이 스킬이 언제 필요한지에 대한 설명
---
```

Claude는 사용자의 요청이 들어오면 이 설명을 기준으로 어떤 스킬을 활성화할지 결정합니다.
예를 들어 "이 PR을 검토해줘"라고 요청하면, Claude는 등록된 스킬들의 설명을 훑어보고 PR 리뷰와 관련된 스킬을 찾아 자동으로 적용합니다.

## 스킬을 저장할 위치

스킬은 저장 위치에 따라 적용 범위가 달라집니다.

### 개인 Skills

홈 디렉터리 `~/.claude/skills`에 저장합니다. 이 Skills는 모든 프로젝트에서 사용할 수 있습니다.

![상세 페이지 화면](/posts/claude-skills/1.png)

커밋 메시지 스타일, 문서 형식, 코드 설명 방식 등 프로젝트에 상관없이 개인적인 선호사항을 담아두기 좋습니다.

### 프로젝트 Skills

프로젝트 루트 `.claude/skills`에 저장합니다. 저장소를 클론하면 팀원 모두가 동일한 Skills를 사용하게 됩니다.

![상세 페이지 화면](/posts/claude-skills/2.png)

팀 코딩 컨벤션, 브랜드 가이드라인, 배포 체크리스트 같은 내용을 넣어두면 팀 전체가 일관된 기준으로 작업할 수 있습니다.

## Skills의 차별점은 무엇일까요?

Claude Code는 동작을 커스터마이징하는 여러 가지 방법을 제공합니다.

**CLAUDE.md**는 모든 대화에 항상 로드됩니다. "TypeScript strict mode를 항상 사용해줘" 같이 전역적으로 적용돼야 하는 설정이 여기 들어가기 좋습니다.

![상세 페이지 화면](/posts/claude-skills/3.gif)

반면에 스킬은 요청과 일치할 때 필요에 따라 로드됩니다.
이름과 설명만 표시되므로 컨텍스트 창 전체를 채우지 않습니다.
디버깅 중에는 PR 검토 체크리스트가 컨텍스트에 표시될 필요가 없습니다.

![상세 페이지 화면](/posts/claude-skills/4.gif)

**Slash Commands**는 사용자가 직접 `/커맨드명`을 입력해야 실행됩니다. 명시적으로 호출해야 한다는 게 포인트죠.

![상세 페이지 화면](/posts/claude-skills/5.png)

## 언제 Skills를 만들면 좋을까요?

> - 팀 코드 리뷰 기준
>
> - 커밋 메시지 형식
>
> - 브랜드 가이드라인
>
> - 문서 작성 템플릿
>
> - 프레임워크별 디버깅 체크리스트

간단한 원칙은 이렇지만 같은 내용을 Claude에게 두 번 이상 설명했다면, 그건 스킬로 만들 신호입니다.

## 마무리

Skills의 핵심은 단순합니다. **반복되는 설명을 한 번만 하자**는 거예요.

한 번 만들어두면 Claude가 알아서 상황에 맞게 적용해주니, 매번 컨텍스트를 설명하는 번거로움 없이 작업에만 집중할 수 있게 됩니다.

개인 작업 습관부터 팀 컨벤션까지, 반복되는 설명이 있다면 Skills로 만들어보세요.
