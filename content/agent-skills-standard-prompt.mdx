Agent Skills는 쉽게 말해 프롬프트를 스킬 단위로 표준화해 재사용하는 방법입니다.
핵심은 한 번 잘 만들어 둔 프롬프트를 특정 에이전트에 묶어두지 않고, 여러 에이전트에서 공통으로 활용할 수 있게 만드는 데 있습니다.

이 개념은 Anthropic의 스킬즈 레포지토리로 많이 알려졌고, 최근에는 Claude뿐 아니라 Gemini, GPT 계열 환경에서도 같은 아이디어로 적용되는 흐름이 이어지고 있습니다.

## 에이전트 스킬즈가 뭔가요?

에이전트 스킬즈는 아래처럼 이해하면 가장 쉽습니다.

- 스킬 = 매우 구체적으로 작성된 프롬프트 템플릿
- 목적 = 반복 작업에 재사용 가능한 지침을 축적
- 동작 = 요청을 받으면 필요한 스킬을 찾고, 맞는 스킬을 시스템 프롬프트처럼 채택해 실행

프롬프트가 구체적일수록 결과물의 일관성이 높아집니다.
스킬즈는 그 구체화된 프롬프트를 잘 모아두고 필요할 때만 꺼내 쓰는 구조입니다.

## Anthropic 스킬즈 레포지토리에는 뭐가 있나요?

예시 스킬은 꽤 다양합니다.

- PDF 생성 관련 작업
- PPT 제작 관련 작업
- 프론트엔드 디자인
- 캔버스 기반 디자인

결국 "이 작업을 에이전트에게 시킬 때 어떤 지침이 가장 효과적인가"를 사례 형태로 담아둔 실전 프롬프트 모음이라고 보면 됩니다.

## 토큰을 많이 쓰지 않나요?

자주 나오는 질문이 하나 있습니다.

> 스킬이 많아지면, 에이전트가 전부 읽느라 토큰을 너무 많이 쓰지 않을까?

이 문제는 보통 front matter 중심 탐색으로 완화합니다.
즉, 처음에는 스킬 본문 전체가 아니라 마크다운 상단의 최소 메타정보만 확인합니다.

- `---` 블록 안의 `name`, `description` 같은 요약 정보 우선 확인
- 현재 요청과 맞는 스킬이라고 판단될 때만 본문 프롬프트 로드
- 결과적으로 초기 토큰 사용량을 줄이고 탐색 효율을 높임

## 스킬 파일 구조

기본 구조는 단순합니다.

- 폴더명 = 스킬 이름
- 폴더 내부에 `SKILL.md` 파일 배치
- `SKILL.md` 상단 front matter에 이름/설명 작성
- 본문에는 실제 실행 지침(프롬프트) 작성

정리하면, front matter는 검색 정확도를 높이는 인덱스이고, 본문은 결과 품질을 만드는 실행 지침입니다.

## 나만의 스킬을 만들어야 하는 이유

스킬 구조의 실전 장점은 "재사용 가능한 자산화"입니다.

- 내가 자주 쓰는 프롬프트를 스킬로 저장
- 작업이 필요할 때 동일 지침을 반복 활용
- 나중에 사용하는 모델이나 서비스가 바뀌어도 자산을 그대로 이전 가능

즉, 프롬프트 운영이 특정 제품에 종속되지 않고 지식 자산으로 축적됩니다.

## 마무리

에이전트 스킬즈는 프롬프트를 표준화된 단위로 쌓고, 필요할 때 정확히 찾아 쓰는 방식입니다.
front matter 기반 탐색을 함께 쓰면 토큰 비용을 줄이면서도 결과 품질을 안정적으로 가져갈 수 있습니다.

작은 반복 작업부터 스킬로 분리해두면, 이후 자동화 속도와 결과 일관성이 눈에 띄게 좋아집니다.
